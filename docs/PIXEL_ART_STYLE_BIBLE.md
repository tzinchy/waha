# WAHA artwork and acceptance baseline

The existing four-faction package is a procedural prototype. It has not passed artistic acceptance. The reference PNG is a visual target, not a game animation. The generated captain walk source in `client/public/art-src/legion/captain/` is rejected: its 1254 px square cannot be split into eight integer-sized cells, and contacts, silhouette bounds and pose scale drift. It is kept for correction and does not replace a runtime atlas.

The agreed visual language is gothic science fiction: cobalt/bronze Legion armour, red/black damaged Heretic armour, green flesh and rusty asymmetric Scrap plates, segmented dark-metal Necrons with green light, narrow purple/turquoise Drukhari blades, and organic Daemon flesh/chitin. An outline must identify its faction and role without a label. Armour joins, rivets, scars and weapons should remain readable at native size. Original insignia only.

Use a 35° elevated orthographic camera and 8 facings. Existing baked metadata describes model forward +Z and camera azimuth 45°. The simulation uses +X forward; the runtime now accounts for that conversion. Source lighting is fixed in screen space: cool fill and warm upper-side rim. Avoid a noisy isolated-pixel outline. Transparencies must have clean edges and no foreign colour halo.

Infantry cell bounds are 96–128 px; captains/elite 128–160 px; vehicles 192–256 px; titans 256–384 px; buildings 192–512 px. Use the same world scale through `camera.orthographicHeight`. Ground anchors are cell-local coordinates recorded in JSON; changing action or facing must not move the contact point. A constant transparent gutter is required. The runtime uses texel-centre UV bounds and metadata frame timestamps, and holds the final non-looping frame.

Inspect every direction at 1× and 2×, a complete motion cycle, and a real match screenshot. Check alternating foot contacts, stable armour/gear, hand grip, correct weapon side, anticipation, impact and recovery. Review the captain, warboss, terminator and monolith slice before expanding the catalog. Palette/pose/lighting approval is a visual decision; a technical validator cannot certify it.

A reviewed source import uses `npm run assets:import -- --faction legion --role captain --action walk --png source.png --json source.json --provenance review.json`. Metadata matches the runtime schema. The review file must give `source`, `rights`, and `visualQA: {status: "accepted", reviewer: "...", evidence: ["..."]}`. The importer rejects invalid dimensions, missing alpha, duplicate facings and clipped frames before replacing any asset; previous working files are backed up in `art-src/previous`. Review evidence must actually exist, not be inferred from this document.

Run `npm run assets:audit` after importing. It inventories physical PNG/JSON and GLB files, reports dimensions, frame occupancy, clipping, missing roles/actions, animation clips and byte sizes, then rebuilds the manifest. This establishes technical validity only. Artistically unapproved procedural files remain marked as prototypes.
