# Фракционные ассеты: первый рабочий проход

Пакет подготовлен на ранней версии WAHA с Three.js. Последующие изменения `main`, включая переход игры на 2D, в эту экспериментальную ветку не перенесены.

Для просмотра без установки скачайте `client/public/art/faction-lab-standalone.html` и откройте файл в браузере. Модели, текстура земли и код уже включены в HTML. Документ проверен с отключёнными сетевыми запросами: сцена, кратеры и экспорт GLB работают.

Выбранные фракции: космодесант, Хаос, орки и некроны. Оригинальные названия армий и эмблемы заданы в пресетах. Визуальное направление — детальный готический sci-fi, читаемые силуэты и пиксельное представление с камеры сверху под углом.

## Рекомендуемый подход

Для текущего Three.js и планов на стрельбу, кратеры и разрушения подходит 2.5D: ортографическая камера, объёмная земля и модели, низкое разрешение с целочисленным масштабированием, спрайтовые эффекты. При фиксированной камере персонажей можно заранее запечь в спрайты, сохранив объёмное окружение.

Рисованная 2D-пехота даёт больше контроля над каждым пикселем, но требует согласованных кадров каждого действия в каждом направлении. В этой заготовке 52 юнита × 5 действий × 8 направлений × 8 кадров = 16640 кадров. Генерация иллюстраций сама по себе не обеспечивает стабильность такой анимации. Запекание одной модели сохраняет пропорции и экипировку во всех кадрах.

Низкое разрешение помогает получить пиксельный вид; финальное качество зависит также от формы, текстур, света и эффектов. Близость к референсу следует оценивать в игровом масштабе. Пакет ниже — процедурный прототип формы и движения. Он ещё не достиг детализации художественного референса.

## Что создано

- `client/public/art/factions-reference.png`: целевой художественный образ четырёх фракций. Нижняя полоса иллюстрирует движение, но не является игровым атласом.
- `client/faction-models.ts`: 52 юнита из подвижных жёстких частей: восемь ролей пехоты и пять типов техники у каждой фракции; десять ролей построек.
- `client/public/models/factions/<фракция>/<роль>/model.glb`: 92 экспортированные модели. Каждый из 52 юнитов содержит пять именованных клипов; всего 260 клипов. Это иерархическая анимация отдельных деталей, без скиннинга и симуляции ткани.
- `.../<роль>/sprites/<анимация>.png` и `.json`: 260 прозрачных атласов 1024×1024; в каждом восемь строк направлений и восемь столбцов кадров. Метаданные задают длительность, цикличность, углы, координаты кадров и опорную точку на земле. Пехота использует окно камеры 5 м, техника — 8 м; масштаб и якорь записаны в JSON.
- `tools/faction-presets.mjs`: художественные пресеты для 92 ассетов, палитры, требования к материалам, бюджетам и анимациям.
- `client/asset-lab.html`: интерактивный полигон. Фракции, анимации, сравнение пиксельного и чёткого представления, залп, кратеры, разрушение штаба и экспорт.

Капитан: `idle`, `walk`, `run`, `attack`, `death`. Пехотинец: `idle`, `walk`, `run`, `shoot`, `death`. Строитель: `idle`, `walk`, `run`, `work`, `death`.

Запуск из корня репозитория: `npm run dev`. Полигон доступен по пути `/asset-lab.html` на этом сервере. `npm test` проверяет симуляцию; `npm run check` проверяет TypeScript.

На полигоне деформируется геометрия земли и остаются следы выгорания. Частицы взрыва временные, у разрушенного штаба остаются обломки. Эти эффекты пока не подключены к сетевой симуляции игры, её столкновениям или поиску пути. Это проверка способа представления, а не завершённая система разрушения мира. В основной игре ещё нет выбора этих четырёх фракций.

## Повторная генерация

При работающем dev-сервере выполните `node tools/bake-factions.mjs`. Скрипт экспортирует текущие процедурные модели и запекает анимации без внешнего API. Обновляются только сгенерированные ассеты в `client/public/models/factions/`.

В этой облачной среде Chromium и Playwright Core уже доступны. На другой машине установите Chromium и Playwright Core отдельно от зависимостей игры. Например:

```sh
npm install --prefix /workspace/scratch/waha-art-tools --cache /workspace/.npm-cache --no-audit --no-fund playwright-core@1.56.0
WAHA_PLAYWRIGHT_MODULE=/workspace/scratch/waha-art-tools/node_modules/playwright-core node tools/bake-factions.mjs
```

`WAHA_CHROMIUM_PATH` задаёт путь к Chromium, `WAHA_DEV_URL` — адрес уже запущенного dev-сервера. По умолчанию используются `/usr/bin/chromium` и порт 5173. Не запускайте несколько Vite-серверов одновременно: HMR использует порт 24678.

## Необязательный Meshy

Существующий генератор расширен фракционными пресетами. `node tools/meshy.mjs --faction necrons --dry-run guard` выводит полный план без ключа, сетевых запросов и оплаты. Аналогично доступны `legion`, `heretics`, `scrap`; без списка ролей выбираются все семь ассетов фракции.

Запуск без `--dry-run` создаёт платные задачи через Meshy и требует `MESHY_API_KEY`. Ключа в среде нет; Meshy-генерация и соответствие её API не проверены. Процедурный пакет выше создан без Meshy. Для сторонней генерации сначала проверьте одного персонажа, его материалы, риг, клипы и соответствие художественному референсу, затем расширяйте пакет. Автоматический выбор первой подходящей библиотечной анимации требует визуальной проверки.

Общий путь вывода Meshy совпадает с процедурным пакетом. Экспортируйте или сохраните текущий пакет перед заменой моделей сторонней генерацией. Основной загрузчик игры сейчас читает другой каталог (`models/meshy`); подключение фракций требует отдельной интеграции.

## Следующие этапы качества

Детальные формы и материалы по художественному листу, оружие и корректные хват/отдача, техника и тяжёлые юниты, спецэффекты по фракциям, локальные повреждения построек. Для массовых армий нужны профилирование и сокращение количества отрисовок; производительность этого полигона не доказывает готовность к сотням юнитов. Полноценная деформация земли потребует согласования с сервером, навигацией и размещением построек.

Текстура земли взята из существующих ассетов репозитория; лицензия находится в `client/public/tex/LICENSE.txt`.

## Расширенный ростер

В ателье доступны командир, стрелок, строитель, снайпер, тяжёлый стрелок, огнемётчик, элита и медик; бронетранспортёр, танк, шагоход, артиллерия и титан. Постройки: штаб, казармы, пост, турель, генератор, завод, оружейная, реликварий, стена и ворота. Выбор роли меняет предпросмотр всех четырёх фракций и экспортируемую модель. Кнопка попадания и анимация гибели создают брызги и следы крови у живой пехоты; техника и некроны дают искры. Восстановление очищает эффекты. Это процедурные прототипы, не финальное качество художественного образца и не новые правила найма сетевого режима.

Хват двуручного оружия: локтевые шарниры видимы; правая рука согнута в плечевом и локтевом суставах, левая рассчитывается двухзвенной IK к цевью после применения отдачи. IK запекается в клипы GLB и кадры PNG. Техника использует отдельные жёсткие узлы, без гуманоидного авторига.

## Проверяемый аудит и импорт художественных атласов

`npm run assets:audit` теперь проверяет фактические PNG/JSON и заголовки/JSON-чанки GLB, записывает `assets/art-audit.json` и пересчитывает manifest. Текущий исходный пакет содержит 92 GLB, 260 PNG и 260 JSON для четырёх фракций; структурная проверка не является художественной приёмкой. В базовой матрице экспортера отсутствуют 342 физических файла (194 модели/анимационные пары), включая две отсутствующие фракции и дополнительные действия существующих капитанов/элиты. Эта матрица — нижняя граница, не всё production-ТЗ.

`client/art-review.html` показывает реальные игровые атласы в 1×/2×, playback, направления, метаданные, исходный референс и отклонённый новый художественный лист. Он сохранён в `client/public/art-src/legion/captain/`; в runtime он не подставляется. Критерии и команда импорта находятся в `docs/PIXEL_ART_STYLE_BIBLE.md`. Импорт требует происхождение/права и реальный протокол художественной приёмки, проверяет альфу, сетку и clipping, сохраняет предыдущие рабочие файлы.

Экспорт прототипов запускается вручную через GitHub Actions или `node --import tsx scripts/export-factions.mjs`. Scope `missing` ищет отсутствующие/нечитаемые файлы по всему каталогу, а не только по двум захардкоженным расам. Scope `all` сохраняет атласы с принятой художественной provenance. Неподдерживаемое действие вызывает ошибку, вместо сохранения `idle` под именем другой анимации. Истинные клипы GLB и число PNG считаются отдельно. Автоматического расширения процедурного пакета при push больше нет: художественный вертикальный срез ещё не принят.

Проигрыватель читает JSON-метаданные: размеры, duration/loop, timestamps, anchor, направления/азимут камеры. Заморожен последний кадр смерти; состав отряда соответствует HP сервера; корпус строителя использует `work`; загрузка завершившаяся после disposal не оживляет объект. Граната передаётся как серверное событие с ID, замахом/полётом и AoE при приземлении; `J` — бросок, `H` — штаб. Для пока отсутствующих художественных действий анимационный coverage по-прежнему неполон.

`npm run smoke` проходит реальное лобби и матч всех шести фракций, проверяет серверную фракцию, движение через ПКМ, гранату через UI и совпадающий ID impact, настоящий бой по WebSocket и завершение апгрейда штаба. Сохраняются PNG/JSON в `artifacts/browser/`. Зелёный smoke доказывает проверенные механики, а не завершённый арт, сетевой выбор карт/команд, XP/экипировку, полёт или полный ростер: эти требования остаются открытыми. FPS отчёта относится к headless Chromium/SwiftShader и режиму «Производительность», с фактическим числом сущностей; 100+ бойцов в нём не подтверждены.
